## Critical Issues (bugs or silent failures in production)

### 1. `generate_resume` and `get_resume` missing from direct-tool mode

**File:** `backend/agents/coaching/agent.py:49-77`

`_get_direct_tools()` registers 12 tools but omits `generate_resume` and `get_resume` from `tools.py`. When the Gateway is down (circuit open), the agent cannot offer resume operations. The user sees the agent refuse to help with resumes during Gateway outages.

```python
# agent.py _get_direct_tools() — add:
from backend.agents.coaching.tools import (
    ...
    generate_resume,
    get_resume,
)
```

### 2. `AGENTCORE_MEMORY_ID` hardcoded wrong in VoicePracticeStack

**File:** `infra/stacks/voice_practice_stack.py:107`

Hardcodes `"regain-coaching-memory"` but the actual memory ID is a UUID generated by the AgentCore custom resource. Voice practice sessions write to a nonexistent memory resource silently.

**Fix:** Pass the real memory ID from AgentCoreStack via `Fn.import_value("RegainAgentCoreMemoryId")`.

---

### 3. `policy_context.py` diverges from `tools.py` field allowlist

**Files:** `backend/agents/coaching/policy_context.py`, `backend/agents/coaching/tools.py:46-63`

`policy_context.py` ALLOWED_PROFILE_FIELDS includes `"targetRoles"` (plural) and excludes `"name"`, `"skillsFocus"`, `"yearsExperience"`, `"yearsInRole"`, `"highestPosition"`, `"story"`, `"coachNotes"`. The Cedar policy and Python allowlist are not in sync — the Gateway path may allow/block different fields than the direct path.

**Fix:** Single source of truth for field allowlists, imported by both modules.

### 4. `flush_pending_messages` is non-atomic (race condition)

**File:** `backend/handlers/shared/thread.py:133-146`

Read-then-unconditional-clear. Two rapid reconnects can duplicate or lose proactive messages.

```python
# thread.py — atomic flush using conditional expression:
def flush_pending_messages(user_id: str) -> List[Dict[str, Any]]:
    table = _get_threads_table()
    try:
        response = table.update_item(
            Key={"userId": user_id, "threadId": "active"},
            UpdateExpression="SET pendingMessages = :empty",
            ConditionExpression="size(pendingMessages) > :zero",
            ExpressionAttributeValues={":empty": [], ":zero": 0},
            ReturnValues="ALL_OLD",
        )
        return response.get("Attributes", {}).get("pendingMessages", [])
    except table.meta.client.exceptions.ConditionalCheckFailedException:
        return []
```

### 5. Conversation history replay may conflict with SessionManager

**File:** `backend/agents/coaching/agent.py:212-219`

Manually appends turns to `agent.messages` after construction, but `AgentCoreMemorySessionManager` is designed to manage session continuity automatically. If the SessionManager also inserts recalled history, turns could be duplicated. This is the most architecturally fragile point — needs verification of what the SessionManager actually injects vs. what manual replay adds.

## High-Impact Performance Issues

### 6. `recall_memory` makes 3 sequential network calls

**File:** `backend/agents/coaching/tools.py:887-894`

Searches 3 namespaces one at a time. Each call is ~300ms-1s. This runs on every session greeting.

```python
# tools.py — parallelize with ThreadPoolExecutor:
from concurrent.futures import ThreadPoolExecutor, as_completed

def recall_memory(user_id, query, tool_context):
    ...
    with ThreadPoolExecutor(max_workers=3) as pool:
        futures = {
            pool.submit(_search_namespace, client, memory_id, ns.format(user_id=user_id), query): ns
            for ns in _MEMORY_NAMESPACES
        }
        for future in as_completed(futures):
            results.extend(future.result())
```

Matches existing parallelization pattern in `DashboardService` and `generator.py:complete_mission`.

### 7. `log_evidence` does a full partition scan to count one skill

**File:** `backend/agents/coaching/tools.py:571-577`

Does `query_all(userId)` with a filter on `skillTag` after writing. With a large evidence vault, this reads every record for the user. The `skill-index` GSI already exists on EvidenceVault (`skillTag`, `createdAt`).

```python
# Use GSI instead of filter scan:
skill_count_resp = db.query(
    table_name="EvidenceVault",
    index_name="skill-index",
    key_expression="skillTag = :tag",
    expression_values={":tag": normalized_tag},
    select="COUNT",
)
skill_evidence_count = skill_count_resp.get("Count", 0)
```

### 8. `generate_daily_mission` uses `db.query()` not `query_all()`

**File:** `backend/engine/generator.py:269-278`

Fetches mission history and evidence using first-page-only `query()`. Users with >1MB of history get silently truncated data for skill gap analysis, difficulty computation, and streak detection. The tools layer uses `query_all()` for the same data — inconsistency between engine and agent views.

**Fix:** Replace `db.query()` with `db.query_all()` in `generator.py` for mission_history and evidence_vault queries.

---

### 9. 500ms reconnect wait is a timeout guess, not event-driven

**File:** `frontend/src/hooks/CoachingContext.tsx:408`

Does `await new Promise((r) => setTimeout(r, 500))` after `connect()`. On slow networks or cold Lambda starts, the WebSocket isn't OPEN after 500ms, causing spurious errors. The message isn't saved to `lastFailedMessageRef` at that point, so it's lost.

**Fix:** Return a Promise from `connect()` that resolves on `auth_success` or rejects on timeout:

```typescript
const connect = useCallback((): Promise<void> => {
  return new Promise((resolve, reject) => {
    // ... existing WebSocket setup ...
    // In onmessage auth_success handler:
    resolve();
    // In onclose/onerror:
    reject(new Error('Connection failed'));
    // Timeout fallback:
    setTimeout(() => reject(new Error('Auth timeout')), 10_000);
  });
}, []);
```

### 10. No frontend progress during compaction

**File:** `backend/handlers/coaching/stream_handler.py:533-550`

Creates a full coaching agent for summarization without `callback_handler` or `hooks`. The user sees a frozen connection for 10-30 seconds.

**Fix:** Send a `{"type": "thinking", "tool": "compact_thread"}` message before starting compaction, and `thinking_complete` after.

## AWS Architecture Improvements

### 11. AgentCore Memory IAM is `resources=["*"]`

**File:** `infra/stacks/agent_stack.py:178-187`

Grants memory operations on all resources. Scope to the specific memory:

```python
resources=[
    f"arn:aws:bedrock:{self.region}:{self.account}:memory/{memory_id}"
]
```

Same for `_agentcore_gateway_policy()` — scope to the specific gateway ID instead of `gateway/*`.

---

### 12. ConversationThreads table has no TTL

**File:** `infra/stacks/data_stack.py:230-245`

Archived thread rows (sort key = ISO timestamp) accumulate indefinitely. Add a TTL attribute:

```python
# data_stack.py — add to ConversationThreads:
time_to_live_attribute="expiresAt"
```

Then in `compact_thread()`, set `expiresAt` on the archive row (e.g., 90 days from now). The active thread row never gets a TTL.

---

### 13. WebSocket Lambdas have no DLQ

If `$disconnect` fails (DynamoDB error during cleanup), there's no retry. Connection metadata leaks until TTL expiry. Add an SQS DLQ to both WebSocket Lambdas:

```python
from aws_cdk.aws_lambda import EventInvokeConfig
from aws_cdk.aws_sqs import Queue

dlq = Queue(self, "ChatStreamDLQ", retention_period=Duration.days(14))
chat_lambda.configure_async_invoke(
    on_failure=destinations.SqsDestination(dlq),
    max_event_age=Duration.hours(1),
    retry_attempts=2,
)
```

---

### 14. SNS alert topics have no subscribers

Both `RegainCoachingAlerts` and `RegainDynamoDBAlerts` exist but have no email/endpoint subscriptions in CDK. Alarms fire into the void. Add at minimum:

```python
from aws_cdk.aws_sns_subscriptions import EmailSubscription
alert_topic.add_subscription(EmailSubscription("team@altivum.ai"))
```

---

### 15. DynamoDB on-demand mode gets no Free Tier WCU/RCU benefit

Free Tier gives 25 WCU + 25 RCU in **provisioned** mode only. For competition-scale traffic, provisioned mode with auto-scaling from 1-25 would be cheaper (free). Evaluate switching the 3 highest-traffic tables (UserProfiles, MissionHistory, ConversationThreads) to provisioned with low baseline capacity.

---

### 16. WAF costs ~$3-5/month minimum (not Free Tier)

**File:** `infra/stacks/api_stack.py:385-438`

WAF WebACL is good for security but costs money. If Free Tier compliance is strict, evaluate whether API Gateway throttling + Cognito auth are sufficient for competition demo.

---

### 17. Cold start: no provisioned concurrency on WebSocket Lambdas

The 212MB Strands layer means 2-5s cold starts on ChatStream and VoiceSession. First message after Lambda recycle is visibly delayed. For competition demo:

```python
alias = chat_lambda.add_alias("live")
alias.add_auto_scaling(min_capacity=1, max_capacity=1)
```

Cost: ~$3.50/month per provisioned instance. Not Free Tier, but prevents a bad first impression in the demo.

## Code Quality Issues

### 18. `_component_cache` has no size limit or TTL

**File:** `backend/agents/coaching/agent.py:24`

Module-level dict grows unboundedly if `$disconnect` is missed (network drop). Add max-size eviction:

```python
from collections import OrderedDict
_MAX_CACHE_SIZE = 50
_component_cache: OrderedDict[str, Dict[str, Any]] = OrderedDict()

# In create_coaching_agent, after caching:
if len(_component_cache) > _MAX_CACHE_SIZE:
    _component_cache.popitem(last=False)  # evict oldest
```

---

### 19. Circuit breaker doesn't trip on tool invocation failures

**File:** `backend/agents/coaching/circuit_breaker.py`

Only records failures during Gateway tool discovery (`agent.py:166`). Individual tool invocations through `gateway_client.py:_handle_client_error` return error dicts but never call `gateway_circuit.record_failure()`. A Gateway that succeeds at discovery but fails on every invocation never trips the circuit.

**Fix:** Call `gateway_circuit.record_failure()` from `_handle_client_error` when the error is `gateway_unavailable`.

---

### 20. Token estimation is `len(content) // 4` across all turn types

**File:** `backend/handlers/shared/thread.py:36`

Same formula for prose, JSON tool results, and code. Tool call results with nested JSON are systematically undercounted (~3 chars/token for JSON, not 4). This delays compaction and risks exceeding Bedrock's actual context window.

```python
def estimate_tokens(content: str, source: str = "text") -> int:
    divisor = 3 if source in ("tool_result", "action_event") else 4
    return len(content) // divisor
```
